# 邀请返利

用户前端：`/affiliate`；后台：`/admin/affiliates/withdrawals`；活动配置：系统设置 → 功能开关 → 邀请返利。

## 规则

- 所有账号自动生成邀请码；已有自定义邀请码和邀请关系保留。注册的可选 `aff_code` 与准入邀请码 `invitation_code` 相互独立。邮箱注册时，用户创建和有效返利码绑定在同一个事务内完成；无效返利码会返回错误。
- 首充赠送比例为百分数，默认 10；只奖励使用有效返利码注册的用户的首次成功余额充值。首充赠送进入个人消费余额，不进入返利账户。失败或取消而未支付的订单不消耗首充资格；历史成功或已退款订单消耗资格。
- 赠送额 = 充值到账基础额度 × 首充赠送比例。若全局充值倍率为 1，支付 1000 元、赠送 10%，共到账 1100 元。比例在下单时保存，支付结算时检查活动是否开启。并发订单按最早付款订单确定首充，赠送领取与余额增加在同一事务中提交。
- 返利只给直接邀请人。返利基数使用订单实付 `pay_amount`，不包含赠送余额；全局返利比例默认 10%，已有全局配置和用户专属比例继续生效。
- 支付宝提现填写账号与实名姓名，金额精确到分，单次申请不得低于提现门槛。提交时预扣可用返利，待管理员手动付款后标记已支付；驳回只退回一次。标记已支付不会调用支付宝转账。
- 转余额一次性转换全部可用返利，必须达到转换门槛，无需管理员审批。提现和转换在同一个返利账户行上串行处理，避免重复花费。
- 后台按天配置返利冻结期（最多 30 天，0 表示不冻结），底层继续使用 `affiliate_rebate_freeze_hours` 保存小时数，7 天对应 168 小时。每笔返利从入账时单独计时；冻结金额计入累计返利及冻结余额，不计入可用余额，不能提现或转余额。到期后，在查看账户、提现或转换余额时自动结算已到期记录；打开中的用户页面也会在最近一笔到期后刷新。配置变更仅影响后续新入账返利，不改变既有记录的解冻时间；关闭活动也不会提前解冻。
- 关闭活动后不再建立邀请关系、赠送首充、产生返利或受理新提现；后台仍可处理已有申请。用户页面和历史记录保留，可按转换门槛继续转余额。

## 退款追回

- 全额退款撤销该订单的全部实发返利和首充赠送；部分退款按退款额度 / 订单基础额度的比例撤销，按原始实发奖励计算并保留 8 位精度，不使用修改后的活动比例。
- 对应返利尚在冻结账户时直接扣除冻结金额；已解冻则扣可用返利。已提现或转余额造成的不足记为待追回，后续即时返利和到期解冻金额先抵扣欠额。其他尚未到期的返利仍按原解冻时间结算。
- 原始返利与累计撤销额均保留，另记 `refund_revoke` 追回流水，按订单累计撤销额保证幂等。累计返利、受邀人记录和上限统计使用扣除撤销后的净额。已全部撤销的金额不会再次解冻。
- 首充赠送从充值用户的消费余额按比例扣回（独立于管理员的充值本金“扣除余额”选项）；如赠送已消费，消费余额可变为负数，由后续充值抵扣。退款不恢复首充资格。
- 关联订单退款处理中暂不能提现或转换该邀请人的返利；冻结到期也等待退款结果。失败后保留奖励，成功后完成冲销。活动关闭不影响退款追回。
- 网关成功后若本地结算失败，订单进入待确认并保留已退款、已扣本金的凭据；后台点击“查询退款状态”重试本地结算，不再次请求网关退款或重复扣本金。待确认订单禁止重新发起退款。

## 配置与迁移

新增配置键：`affiliate_first_recharge_bonus_percent`（0–100）、`affiliate_withdraw_minimum`、`affiliate_transfer_minimum`（金额，0 表示不设门槛）。保留现有返利比例、冻结期和用户专属配置。

账户接口返回 `rebate_freeze_hours`、`next_thaw_at`；返利流水及受邀充值记录返回逐笔 `frozen_until`。冻结配置读取异常时停止该笔返利入账并交由支付履约重试，避免把异常视为不冻结。退款成功时在同一事务中撤销该订单对应的返利与首充赠送，失败或处理中不冲销。账户额外返回 `aff_debt_quota`（待追回金额）；记录返回 `reversed_amount` 和 `source_order_id`。

迁移 `269_affiliate_refund_reversals.sql` 增加奖励累计撤销字段，沿用有符号返利余额保存待追回欠额。迁移 `268_affiliate_wallet_and_first_recharge.sql` 创建提现、首充领取表，补齐已有账号的邀请码，并为新账号插入邀请码。应用启动的迁移流程负责执行；部署应同时包含新版后端、管理后台与用户前端。

## 接口

- `GET /api/v1/user/aff`：活动状态、邀请码、返利余额、比例和门槛。
- `GET /api/v1/user/aff/records?kind=invites|recharges|ledger|withdrawals&page=1&page_size=20`：当前账号的分页记录；普通用户看到的受邀邮箱脱敏。
- `POST /api/v1/user/aff/withdrawals`：`amount`、`alipay_account`、`alipay_name`。
- `POST /api/v1/user/aff/transfer`：转换全部可用返利。
- `GET /api/v1/admin/affiliates/withdrawals`：分页提现申请。
- `PUT /api/v1/admin/affiliates/withdrawals/:id`：`status`（`paid` / `rejected`）、`admin_note`。
- `GET /api/v1/admin/affiliates/users/:user_id/detail`：用户返利账户详情。
- `GET /api/v1/admin/affiliates/users/:user_id/records`：指定用户分页记录，参数同用户记录接口。

## 数据库验证

资金事务测试可使用独立 PostgreSQL 测试库。设置 `AFFILIATE_TEST_POSTGRES_DSN` 后，执行 `go test -tags=unit ./internal/service ./internal/repository -run 'Affiliate|Refund'`。测试在专用临时 schema 内创建表并在结束时清理；未设置环境变量时跳过 PostgreSQL 用例。
